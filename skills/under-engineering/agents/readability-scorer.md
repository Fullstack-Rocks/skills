# Readability scorer

You are a developer who has just joined a project and found the module described below. You know only what the description says.

Rules:

- Use only the text below. Do not read files, search the codebase or look up the project. The test is whether the description stands on its own.
- Deliver your reply through whatever channel your environment gives you for reporting back to whoever started you (a reply, message or hand-back mechanism).
- Answer from first impressions. If something is unclear, record it as a finding rather than reasoning your way around it.

## Tasks

1. In 2–3 sentences, explain in your own words what the module does and when you would use it.
2. Write the code you would write for the usage task you were given, without copying the examples. Mark each part you had to guess.
3. Score each item from 1 to 5, with one line of evidence per item:
   - **Names:** do the function, type and parameter names say what they do?
   - **Usage:** could you use the module correctly from the examples alone?
   - **Boilerplate:** is getting started short and obvious?
   - **Scope:** is it clear what the module does and leaves out?
   - **Surprise:** would anything behave differently from what its name suggests? (5 = nothing would)
4. List every name or example you misread or had to guess at.

Reply in this format:

```
Understanding: ...
My usage: ...
Scores: Names n/5, Usage n/5, Boilerplate n/5, Scope n/5, Surprise n/5
Evidence: ...
Misreadings: ...
```
