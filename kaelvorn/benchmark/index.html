Kaelvorn: build and redesign benchmark

One Claude Code orchestrator on Claude Opus 5.5 commissioned research, art, implementation and reviews through the delegate skill. The result is the live Kaelvorn site: 37 prerendered pages for a fictional upcoming MMORPG, with 13 Callings, four full dossiers, skill trees and a painted atlas. The redesign brought the implementation closer to its painted concepts, adding a central HUD, a heraldic logo, brush masks, crown moulding and painted interface icons.

What the plan workflow changed

Checked consumers before launch. plan check caught two outputs with no consumer before wave 1 started. The decision log does not name the two files, so they cannot be identified from these inputs; the useful change was requiring an explicit handoff for every output, instead of assuming generated work would be integrated.

Reassignment kept the work moving. Antigravity exhausted its account quota, with a reported reset roughly 125 hours away; audit, ornaments, masks and ui-icons could not finish there. The plan moved audit/review to Codex with headless Chrome and image-making units to Cursor GPT-5.6 Sol, retaining Nano Banana through gemini-api image; logo-final changed assignment before an Antigravity run was launched.

Send-backs preserved context and respected new code. The first visual review's 19 findings went back to codex-30 for shared components, while page fixes started on a fresh Cursor worktree because cursor-11 predated the shared changes. Re-review still found three regressions—mobile launch art below the fold, fragmented “Revealed soon” text and copy over brush fringes—so cursor-12 received another follow-up; the orchestrator also returned clipped/doubled header branding to its shell owner.

Left open became an owned deliverable. The SVG unit's README exposed that the audit called for a painted world atlas, but no unit made it. The orchestrator added atlas, accepted its 3:2 painting and six pin positions, then sent it to the existing shell builder as an attached follow-up; acceptance by consumers also determined when upstream units closed.

Incremental application needed an explicit contract. The benchmark brief identifies incremental diff --apply as a skill fix discovered during the workflow: repeated follow-ups require applying the new delta against already accepted work. The supplied decision log does not describe its implementation or verification, so this report records the fix without claiming a particular patch algorithm or test result.

Follow-up timeouts must inherit the run's settings. codex-30's third turn hit 30 minutes because send ignored the timeout used by start; the decision log records a skill fix. A follow-up is part of the same long-running unit and needs its execution settings carried forward along with its context.

Completion needs a parseable status line. The benchmark brief lists a status-line skill fix, and the delegate brief requires a final STATUS: done, STATUS: question … or STATUS: blocked … line. That gives the orchestrator an explicit terminal outcome beside the deliverables and Left open list; the supplied sources do not detail the parser change.

Nobody approves plans mid-turn. cursor-12 initially ended empty after creating a plan for approval, so it was sent back; the skill now tells delegates nobody approves plans during their turn. Delegates must execute within the brief, or finish with a concrete question when an orchestrator decision is essential, rather than wait for an interactive approval that cannot arrive.

Build lessons retained

Cursor delegated the builder’s entire job. Builder C read the orchestrator’s CLAUDE.md, assumed that role and launched a 1,475-second Codex worker; its implementation was accepted, but its decision-log edits were discarded. The delegate lesson is to make role and scope explicit in every brief: subsequent briefs say the agent is a delegate, must do the work itself and must not edit the decision log; account for nested workers under their actual harness.

A foreground server consumed the browser reviewer’s turn. The decision log says Antigravity’s first review turn timed out while running vite preview in the foreground, and a second turn wrote findings from 46 screenshots. The skill lesson is to start persistent servers in the background and preserve evidence between turns; the snapshot records only one turn for antigravity-8, so it cannot quantify the missing attempt separately.

Builder B found a production hydration deadlock in A’s shell. A top-level await import() in preferences.tsx blocked production hydration even though earlier checks had passed. The fix became a separate Codex run with npm run smoke: delegated handoffs need a built-site browser check of real interaction, not just compilation and unit tests.

Budget gates stopped integration twice. Builder A’s shell measured 102.4 KiB gzip against a 100 KiB gate; the orchestrator raised it to 110, then later raised home/static route gates from 160/150 to 175/160 after measuring 166.5/150.6. The lesson is to give delegates a measured dependency baseline and an escalation path for budget changes, then require performance evidence: Lighthouse subsequently identified a real late-CSS defect rather than treating the relaxed gates as proof of acceptable UX.

Ownership boundaries still needed an integration pass. B’s WorldMap brought its own h2 into C’s /world section, breaking one integration test; the integration worker corrected the page structure instead of changing the assertion. The skill should specify shared component contracts, merge checkpoints and an integration owner; phase 8 then split copy, A/B and C fixes by ownership so parallel agents would not edit the same files.

Reviews and fixes needed more than one round. Three phase 7 reviewers returned 17 marketing, 12 browser and 9 performance findings; fixes reached 257 tests and 11 smoke checks and raised character-page desktop Lighthouse from 79 to 100, but the browser/Grok re-checks found incomplete fixes and new regressions. After a final fix run, the orchestrator’s own visual pass still found four polish issues, so the lesson is to budget for independent re-checks and a final visual acceptance pass, with concrete routes, widths and evidence in every fix brief.

Art delivery hid substantial iteration. All 56 phase 5 Codex finals were accepted by the orchestrator, yet the complete ledger records 40 discarded Codex attempts across style and production work, plus two discarded Nano Banana sheets. The skill should preserve per-attempt image counts, native dimensions and rejection reasons; final file counts alone understate generation cost and the effort needed for consistent art.

Scope, timing and verification limits

  • Elapsed versus summed time: the original build's commit bracket ran from 2026-10-25 23:07:26 to 2026-10-26 03:49:19 (+02:00), 4h 41m 53s; including its first benchmark turn estimated roughly 4h 51m. Those are historical estimates, not updated stage wall times. usage.json has durations without start/end timestamps, so redesign elapsed time and active orchestrator hours cannot be recovered.
  • Nested overlap: cursor-2's 1,599 seconds contain its 1,475-second nested Codex worker. Subtracting that interval once yields build 8h 43m 02s, and both stages 13h 52m 14s; this still is not wall time because other workers overlapped. Runs count unique delegation records, turns include recorded follow-ups.
  • Snapshot gaps: the decision log describes more cursor-12 follow-up activity than its two recorded turns, and Antigravity's build browser retry is not fully represented by its turn count. Outcomes follow the final decision log; quantitative usage follows usage.json without inventing missing tokens/time. The current writer and later orchestrator work are outside the snapshot.
  • Valuation limits: token categories vary by harness; Standard speed and the stated approximate context tiers are assumptions. Excluded items include separately unreported cache writes, image prompt/reference and image-model text/thinking charges, tool/search charges, taxes and subscription fees. Agent cost_usd zeros in the JSON are not invoices.
